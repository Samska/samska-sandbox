## Local Development Launcher Maintenance (#50)

- State changes: `scripts/dev.sh` verifies process-group ownership without `ps`, treats a valid `JAVA_HOME` as the authoritative Java selection and prepends it to `PATH` for child processes, refuses to start when the required backend (8080) or frontend (5173) port is already in use, and accepts backend health only while its own backend process group is running. This fixes the Windows Git Bash `Error: Unable to determine the Java version from PATH.` failure caused by a legacy Oracle `java8path` shim ahead of the JDK, and prevents a second launcher instance from attaching to another instance's stack. The `PATH` prepend normalizes `JAVA_HOME` (Git Bash conversion through `cygpath` when available, trailing-separator stripping) and appends `/bin` exactly once, so Linux/macOS shells without `cygpath` do not receive a doubled `/bin` segment. `docs/LOCAL-DEVELOPMENT.md` and the `ss-023` learning note document the behavior.
- Decisions: `JAVA_HOME` outranks `PATH` when it selects a valid Java 25 JDK; a differing or unreadable `PATH` `java` is informational; the launcher never signals a process that owns a required port; the existing process-group supervision and cleanup design is unchanged.

A focused harness extracted `java_home_bin_path` from the launcher and exercised both path-construction branches: with `cygpath` (Windows `JAVA_HOME` with a trailing backslash and spaces) and without it (POSIX `JAVA_HOME` with a trailing slash on a minimal `PATH`); both produced exactly `<normalized JAVA_HOME>/bin`, and the selected `java` and `javac` reported 25.
