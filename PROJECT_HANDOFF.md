## SS-032 — Implement Checkout vertical slice (#53)

- State changes: Checkout is an editable live view of the current authoritative Cart. A non-empty Cart exposes a Checkout action in the Cart drawer; entering Checkout is a local view transition that creates no backend resource, clears any selected Product, closes the drawer directly, and focuses the Checkout heading. The Checkout surface renders the same editable Cart item row as the Cart drawer (quantity increase, decrease, direct input, and removal) using the existing Cart API and the shared `CartItemRow` component; `Catalog` remains the single owner of the Cart state, and every server response updates it, so Checkout immediately shows server-returned quantities, line subtotals, and total. Pending state, the existing Cart error alert, and a "Reload Cart" action are visible on Checkout. Contextual focus recovery keeps keyboard editing context: a quantity mutation restores the same control (or the item's quantity input), a non-final removal focuses the adjacent remaining item, and removing the final item keeps Checkout open and focuses the empty-state heading. No Cart trigger is rendered inside Checkout. The owner superseded the earlier immutable-snapshot and read-only-review semantics (2026-09-23); the backend Checkout module, identity, storage, API, and the `CartQuery`/`CartContents`/`CartLine` contract remain removed. `Cart.snapshot()` remains the atomic Cart read primitive, and `CartResponse.from` serializes one snapshot without changing the Cart API JSON contract. Cart remains the only monetary calculation owner. The immutable transactional snapshot is deferred to Payment Simulator initiation; Order will later derive from the payment result.
- Decisions: Checkout = editable live view of the current Cart; no Checkout identity, state, storage, or mutation logic; editing reuses the existing Cart handlers and API; `CartItemRow` reuse is based on demonstrated duplication; the Cart trigger is intentionally omitted from Checkout; contextual mutation focus recovery is preferred over returning to Back to Market; the atomic `Cart.snapshot()` is an internal Cart read-consistency mechanism, not a Checkout snapshot; an empty Cart stays in Checkout with an empty state; Back to Market always returns to Product Browse; no router, global state, dependency, authentication, payment, Order, persistence, or currency; no ADR because the revision follows accepted [ADR 0001](docs/adr/0001-adopt-modular-monolith.md). Durable sequencing: authentication/authorization is deferred until after the local First Order MVP but is mandatory before any hosted environment, and no hosting work begins before the MVP.
- Agent Verification: backend `./mvnw --batch-mode --no-transfer-progress clean verify` passed 47 tests (Cart snapshot consistency and snapshot value-object independence plus existing Catalog/Cart regressions); frontend `npm run typecheck`, `npm test` (54 tests across 8 files), and `npm run build` passed; markdownlint-cli2 v0.23.3 reported 0 issues across 44 repository Markdown files, relative links resolved, and `git diff --check` was clean; EditorConfig content rules (final newline, no trailing whitespace, no BOM, LF) were verified manually because the editorconfig-checker binary is unavailable locally.
- Human Verification: passed on 2026-09-23 based on the owner's manual validation of the running implementation and acceptance report.
- Delivery: PR [#54](https://github.com/Samska/samska-sandbox/pull/54) carries the SS-032 implementation and is the authoritative CI record. CI Verification must be successful on the exact final PR head before merge, and merge requires explicit owner authorization.

- Completed and merged via PR #52 (squash commit `20d9610`): the Catalog UI is split into `ProductBrowse`, `ProductDetail`, `ProductSetupTools`, and `ProductMedia` over a small shared `Button`, `FormField`, and `StatusMessage` primitive layer; browse and detail hierarchy, feedback tones, placeholder and empty states, and focus return to the originating View details control are refined; amounts are grouped without a currency symbol.
