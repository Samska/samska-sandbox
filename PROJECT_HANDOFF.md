## SS-031 — Elevate Product Storefront UX/UI (#49)

- State changes: owner approved (2026-09-22) that the Product Storefront UX/UI refinement precedes Checkout; README.md and docs/ROADMAP.md reflect the approved order with SS-031 as active work before Checkout. The Catalog UI is split into `ProductBrowse`, `ProductDetail`, `ProductSetupTools`, and `ProductMedia` over a small shared `Button`, `FormField`, and `StatusMessage` primitive layer; browse and detail hierarchy, feedback states, placeholder and empty states, and focus return to the originating View details control are refined; the blanket `[role="status"]` color rule was replaced by explicit feedback tones; amounts are grouped without a currency symbol. Product now carries an optional nullable `mediaKey` (lowercase slug, 40-character limit; blank or malformed rejected; well-formed unmapped keys accepted) through the domain, create request, and response; `web/src/catalog/mediaCatalog.ts` maps curated keys to rights-verified, optimized local assets in `web/public/media/` documented in `ATTRIBUTION.md`, and a monogram fallback covers absent, unmapped, or failed media without layout shift. The permanent Cart sidebar is replaced by a visible trigger and an accessible drawer with dialog semantics, focus entry, Tab containment, Escape and close behavior, focus return, and internal scrolling; "items" means the sum of item quantities in the trigger, drawer, accessibility labels, and tests. The Cart API contract and Cart behavior are unchanged, and Catalog changes only by the optional `mediaKey`; the dependency set is unchanged. [ADR 0003](docs/adr/0003-adopt-optional-product-media-reference.md) records the media-reference decision. The implementation is complete on the short-lived `feat/ss-031-product-storefront` branch and is not merged. PR #52 is open on the branch, and its initial head `b88999a` passed all CI checks. A read-only review found that Shift+Tab from the initially focused `Your Cart` heading could move focus behind the modal, and a follow-up Chromium investigation reproduced a second containment defect: during any pending Cart mutation the focused control becomes disabled, Chromium moves focus to `document.body`, and the next Tab reaches the page behind the modal. Both corrections (reverse-tab wrapping from a non-listed active element, and a focus-recovery effect that moves focus to the first enabled control when the active element is outside or disabled while the dialog is open) are complete on the branch. After the focus correction was finalized, the owner identified one remaining visual defect: the browse grid used `repeat(auto-fill, minmax(14rem, 17.5rem))`, which capped each track at 17.5rem (280px) and left unused width at the right. The correction replaces it with explicit equal-width columns (1 default, 2 at 32rem, 3 at 47rem, 4 at 62rem) so the desktop grid fills the full content width.
- Decisions: bounded "refined market storefront" direction using existing Tailwind `@theme` tokens; explicit media assignment only, resolved by one reviewed static mapping with no external runtime image URLs, uploads, media edit endpoint, or Cart media fields; CC0 assets preferred, with the single CC BY 2.0 asset attributed; amounts stay free of an invented currency symbol; the Cart drawer adds no router or global state; In Cart hints, loading skeletons, new tokens, routing, global state, and an ADR for local UI primitives excluded; owner-approved Storefront-before-Checkout order.

Backend `./mvnw --batch-mode --no-transfer-progress clean verify` passed 45 tests. Headless Chrome at 1440x900 and true 390x844/360x800 confirmed the four browse cards use a full-width 16/10 media region with aligned price and action rows, the three curated images load at 800px with the monogram fallback for the Product without media, the Cart trigger reports the quantity-summed count, and the mobile Cart drawer is full-bleed at 88dvh with internal scrolling, a reachable total, and unchanged desktop bounds (design-review evidence; not a substitute for Human Verification). markdownlint-cli2 v0.23.3 (markdownlint v0.41.1): 0 issues across the 43 repository Markdown files including the new ADR and attribution; `docker compose config --quiet` exit 0 with `POSTGRES_PASSWORD` set (static check, daemon not required); `git diff --check` clean; EditorConfig content rules (final newline, no trailing whitespace, no BOM, LF in the repository via `core.autocrlf=true`) verified for all changed and untracked text files. lychee and editorconfig-checker binaries were unavailable locally; the Repository validation job runs them on the pull request. The reverse-tab correction wraps reverse tabbing from any active element outside the trap list, including the initially focused heading, to the last enabled control. The pending-transition defect was reproduced in headless Chromium with held Cart requests (focus moved from the clicked control to `document.body` and Tab reached the page's skip link); after the focus-recovery effect, focus stayed on `Close Cart` during pending and after completion for quantity increase, enabled decrease, remove, and a simulated failed mutation.
