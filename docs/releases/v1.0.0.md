# v1.0.0 — Secured Public Demo

- Status: Prepared; awaiting owner validation and publication. No tag or GitHub Release exists.
- Candidate: the `release/1.0` integration branch, merged into `main` in one change after the owner validates it.
- Release type: major milestone release; the first stable version.
- Release assets: source only.

## What This Milestone Delivers

A synthetic-data, simulated-payment storefront that can be hosted as a public demo:

- **Durable Store (v0.2.0).** Products, media, Carts, Payment attempts and Orders in PostgreSQL.
- **Accounts (v0.3.0).** Sign-in without self sign-up (SS-095: the administrator is the only user), server-side sessions with CSRF protection, an administrator role, and per-account Cart, Payment attempts and Orders ([ADR 0013](../adr/0013-adopt-account-sessions-and-ownership.md)).
- **Order history and tracking (v0.4.0).** Order history and tracking, with each Order's status set by the administrator ([ADR 0021](../adr/0021-administrator-sets-order-status.md)).
- **Inventory (v0.5.0).** Stock per Product, reserved when a Payment attempt is approved and consumed when the Order is created, with sold-out states and an Admin Stock field ([ADR 0015](../adr/0015-add-inventory-with-reservations.md)).
- **Operations (v0.6.0).** An administrator screen with Orders per hour, approval rate, checkout latency p95, server error rate and service health, plus correlation IDs and structured request logs ([ADR 0016](../adr/0016-observe-requests-with-correlation-ids.md)).
- **Admin area and hosting (v1.0.0).** A separate Admin shell and role-based sign-in destination, a Caddy-fronted Compose stack with automatic TLS that starts private (password in front of the whole site) and switches to the public demo by configuration, and deploy, backup and restore scripts ([ADR 0019](../adr/0019-separate-admin-area-and-terminate-tls-with-caddy.md)).
- **Secured public demo (v1.0.0).** Rate limiting, security headers, a `prod` profile that refuses unsafe settings, a [Threat Model](../THREAT-MODEL.md), a synthetic-data reset and a containerized runtime ([ADR 0017](../adr/0017-harden-the-public-demo.md), [ADR 0018](../adr/0018-add-demo-mode-and-containers.md), [Deployment](../DEPLOYMENT.md)).

## Verification Provenance

- **Agent Verification.** Every change merged into `release/1.0` passed the backend `verify` suite against PostgreSQL, web unit tests and typecheck, and the Playwright browser suite locally and in CI. The final run on the release candidate is recorded in the pull request that merges it.
- **Container verification.** The hosted-demo Compose stack was started locally with the `prod` profile and exercised through the web server (see [Deployment](../DEPLOYMENT.md)).
- **Human Verification.** Pending: the owner validates `release/1.0` locally before the merge to `main`.

## Deliberate Limitations

Never presented as resolved:

- Synthetic data and simulated payments only; no real payment provider, courier, email or identity provider.
- A single application process: sessions, rate limits and request metrics are in memory and reset on restart.
- There is no email verification, password reset or multi-factor sign-in.
- The mobile layout is a responsive web design; there is no native app.
- Hosting is the owner's choice. The public demo runs on Railway from the same images and configuration (see [Deployment](../DEPLOYMENT.md)); the Caddy certificate flow and the backup and restore scripts of the VPS option have not been exercised on a real server.
