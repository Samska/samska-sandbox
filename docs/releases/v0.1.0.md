## What This Milestone Delivers

The local, synthetic First Order MVP of Samska Sandbox:

- **Catalog.** Product creation, collection browsing, identity retrieval, full update, and deletion with a `409` Cart-conflict refusal; descriptions and optional curated or uploaded media with a monogram fallback.
- **Cart.** A process-local Cart with quantity changes, removal, and server-calculated totals.
- **Checkout.** An editable live view of the authoritative Cart; payment initiation captures a revision-checked immutable Cart snapshot.
- **Simulated Payment.** Three explicit local-demo outcomes (Approve, Decline, Temporary failure), identified attempts with same-ID replay, GET reconciliation, and one approval per unchanged Cart revision, held in a bounded process-local store.
- **Order.** Explicit creation from an approved attempt into an immutable process-local record, with same-attempt replay and lookup.
- **First Order journey.** Attempt-addressed surfaces: `/checkout` hosts the editable live Cart, and `/checkout/attempts/{attemptId}` recovers the simulated payment result or Order confirmation through read-only lookups after a full-page reload, direct entry, or history navigation.
- **Admin Catalog Management.** A separate frontend Product-management surface at `/admin/products` over the same unauthenticated Catalog API; it is navigation, not access control.

## First Order Journey

With one synthetic Product prepared through Admin, the implemented journey is: browse the Market → add to Cart → edit Checkout → simulate a payment outcome → explicitly create an Order → retrieve the confirmation, including after reload, direct entry, and history. Recovery is GET-only: it never resends a Payment or Order request, renders from the captured snapshot or frozen Order even when live Cart or Catalog loading fails, and requires an explicit choice before a new journey replaces an unresolved reference. Creating an Order never clears the live Cart, and one browser-held reference is only a discovery hint.

## How To Run It Locally

Install the repository's Java 25 and Node 24.20.0 prerequisites and follow [Local Development](../LOCAL-DEVELOPMENT.md). All data must be synthetic and all payments are simulated; no real payment, credential, or customer data is involved.

## Deliberate Limitations

- **Process-local and non-durable.** Products, Cart, uploaded media, simulated Payment attempts, Orders, and duplicate protection are held in backend process memory and are lost on restart; the guarantees are single-process only. PostgreSQL is optional local Compose infrastructure and is not integrated with the application.
- **No authentication or authorization.** Catalog, Cart, Payment, and Order APIs are unauthenticated; `/admin/products` hides nothing from the API; the simulated-payment endpoints are a local-only demonstration capability and must never be exposed as a hosted simulation or payment capability.
- **No hosting or persistence.** There is no deployed environment, database connection, or persistence layer.
- **No automated browser end-to-end coverage.** Real-browser behavior rests on the owner-reported Human Verification and focused local runtime checks.
- **Synthetic data and simulated payments only.** No real financial transaction, provider, card data, or credential exists.
- **Bounded capacity.** At most 32 Payment attempts and 32 Orders without eviction, and fixed Product media limits.
